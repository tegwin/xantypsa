# Xanty PSA - Installation

Getting a working instance from nothing. Takes about 15 minutes, most of it
waiting for Supabase to provision.

If you already have a running instance and just want to ship it, see
[DEPLOYMENT.md](./DEPLOYMENT.md).

---

## What you need first

| | |
|---|---|
| **Node.js 20 or newer** | `node -v`. Built and tested on Node 20-25. |
| **A Supabase account** | Free tier is fine. Provides both the database and login. |
| **An Anthropic or OpenAI API key** | Optional - only for the AI assistant. Everything else works without it. |

There is no local database to install and nothing to run in Docker. Supabase
provides Postgres and authentication, so the same setup works on your machine
and in production.

---

## 1. Create the Supabase project

1. At [supabase.com](https://supabase.com) → **New project**.
2. Pick a region close to your users and set a strong database password - 
   **save it now**, it appears in your connection string and is not shown again.
3. Wait for provisioning (~2 minutes).

Then collect five values. From **Settings → API**:

- **Project URL** → `NEXT_PUBLIC_SUPABASE_URL`
- **anon / public key** → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- **service_role key** → `SUPABASE_SERVICE_ROLE_KEY` *(secret - server-side only)*

From **Settings → Database → Connection string**:

- **Transaction pooler** (port 6543) → `DATABASE_URL`
- **Session pooler** (port 5432) → `DIRECT_DATABASE_URL`

> The transaction pooler is the one that matters. Serverless functions open many
> short-lived connections and will exhaust a direct connection under any real load.

## 2. Configure the app

```bash
git clone <your-repo-url> xantypsa
cd xantypsa
npm install
```

No flags needed. (If you're on an older checkout that still has `next-auth` in
`package.json`, you'll need `--legacy-peer-deps` - that dependency has since
been removed.)

Create `.env` in the project root:

```bash
# Database - both from Supabase → Settings → Database
DATABASE_URL="postgresql://postgres.<ref>:<password>@<region>.pooler.supabase.com:6543/postgres?pgbouncer=true"
DIRECT_DATABASE_URL="postgresql://postgres.<ref>:<password>@<region>.pooler.supabase.com:5432/postgres"

# Auth - from Supabase → Settings → API
NEXT_PUBLIC_SUPABASE_URL="https://<ref>.supabase.co"
NEXT_PUBLIC_SUPABASE_ANON_KEY="eyJ..."
SUPABASE_SERVICE_ROLE_KEY="eyJ..."

# Encrypts stored LLM provider API keys - generate with: openssl rand -hex 32
AI_ENCRYPTION_KEY="<64 hex characters>"
```

Generate the encryption key:

```bash
openssl rand -hex 32
```

> **Every variable must be on its own line.** Two on one line silently corrupts
> both - a genuinely confusing failure to debug.

## 3. Create the schema

Either route produces the same result - 58 tables, 106 foreign keys.

**With the repo checked out (normal):**

```bash
npx prisma db push
```

Prints a data-loss warning on an empty database; that's expected the first time.

**Without Prisma - plain SQL:**

`sql/schema.sql` is a complete, self-contained PostgreSQL script. Use it when
provisioning a database on its own, or when handing the app to someone else.

```bash
psql "$DATABASE_URL" -f sql/schema.sql
```

Or paste it into **Supabase → SQL Editor → Run**.

Run it against an **empty** database - it creates objects and drops nothing, so
re-running against a populated database fails on the first existing table.

> Regenerate it after any schema change, or it will drift:
> ```bash
> npx prisma migrate diff --from-empty \
>     --to-schema-datamodel prisma/schema.prisma --script > sql/schema.sql
> ```

Optionally load demo data:

```bash
npm run db:seed
```

## 4. Point Supabase back at your app

Password reset and confirmation links are generated by Supabase and must know
where to send people. In **Supabase → Authentication → URL Configuration**:

- **Site URL** - `http://localhost:3000` for now
- **Redirect URLs** - add `http://localhost:3000/auth/callback`

Skip this and sign-in works but password reset silently fails.

---

## 5. Create your first user

Users live in Supabase Auth and are mirrored into the app database. The first
one has to be made by hand.

**In Supabase → Authentication → Users → Add user:** enter an email and
password, and tick **Auto Confirm User**.

**Then link it to a tenant.** Run this from the project root - it creates the
tenant, an owner role with full permissions, and the app-side user record:

```bash
node --env-file=.env -e "
const { PrismaClient } = require('@prisma/client');
const { createClient } = require('@supabase/supabase-js');
const p = new PrismaClient();
(async () => {
  const email = process.argv[1], name = process.argv[2] || 'Admin';
  const admin = createClient(process.env.NEXT_PUBLIC_SUPABASE_URL, process.env.SUPABASE_SERVICE_ROLE_KEY);
  const { data } = await admin.auth.admin.listUsers();
  const authUser = data.users.find(u => u.email.toLowerCase() === email.toLowerCase());
  if (!authUser) throw new Error('Create the user in Supabase Auth first');

  const tenant = await p.tenant.create({ data: { name: name + \"'s Company\", slug: 'default' } });
  const { ALL_PERMISSIONS } = require('./src/lib/permissions.ts');
  const role = await p.role.create({ data: { tenantId: tenant.id, name: 'Owner', slug: 'owner', permissions: [], isSystem: true } });
  const user = await p.user.create({ data: { email, name, supabaseId: authUser.id, isSuperAdmin: true } });
  await p.tenantUser.create({ data: { tenantId: tenant.id, userId: user.id, roleId: role.id, isOwner: true } });
  console.log('Created tenant + owner for', email);
})(process.argv[1], process.argv[2]).finally(() => p.\$disconnect());
" your@email.com "Your Name"
```

The user is created as a **super admin**, which bypasses permission checks - so
an empty permissions array is fine for the first account.

## 6. Run it

```bash
npm run dev
```

Open <http://localhost:3000> and sign in with the Supabase credentials from
step 5.

---

## 7. Turn on the AI assistant (optional)

**Settings → AI → Add a provider.** Choose Anthropic or OpenAI, paste an API
key, and press **Test** - it round-trips a real prompt, so you find out
immediately whether the key works.

The assistant then appears on every screen and knows which module you're on. It
learns your database structure automatically by reading the Prisma schema, so
it stays current as the app changes.

**Self-hosted models** (Ollama, vLLM, LM Studio) are supported as a fallback for
private or offline use - add the provider with a base URL such as
`http://localhost:11434/v1`. Keep Anthropic or OpenAI as the default: smaller
local models are noticeably less reliable at the multi-step tool calling the
assistant depends on.

## The stack

| Layer | Choice | Notes |
|---|---|---|
| Framework | **Next.js 14** (App Router) | Server components by default; API routes under `src/app/api`. |
| Language | **TypeScript 5** | `npx tsc --noEmit` type-checks without building. |
| Database | **PostgreSQL** via Supabase | Accessed through Prisma; ~60 models. |
| ORM | **Prisma 5** | `prisma/schema.prisma` is the source of truth - the AI assistant reads it too. |
| Auth | **Supabase Auth** (`@supabase/ssr`) | Cookie sessions refreshed in middleware. Replaced NextAuth. |
| Styling | **Tailwind CSS 3** | Dark-mode-first; see below. |
| Fonts | **Geist Sans / Geist Mono** | Loaded via the `geist` package as CSS variables. |
| Icons | **lucide-react** | |
| Tables | **@tanstack/react-table** | |
| Charts | **Recharts** | |
| PDFs | **jsPDF + jspdf-autotable** | Quote and invoice generation. |
| Toasts | **react-hot-toast** | |
| Validation | **Zod** | |
| Dates | **date-fns** | |
| AI | **@anthropic-ai/sdk**, **openai**, **@modelcontextprotocol/sdk** | Anthropic and OpenAI are primary; any OpenAI-compatible server (Ollama, vLLM, LM Studio) works as a fallback. |

### Styling

Tailwind with a custom two-colour palette defined in `tailwind.config.ts`:

- **`brand`** (50-950) - blue, `#1e6af5` at 600. Primary actions, links, active nav.
- **`surface`** (50-950) - slate, `#020617` at 950. Backgrounds, borders, body text.

`darkMode: 'class'` with `<html class="dark">` set in the root layout - the app is
dark-mode-first and does not currently ship a light theme.

A small set of component classes lives in `src/app/globals.css` rather than being
repeated across files:

| Class | Purpose |
|---|---|
| `.glass-panel` | The frosted card used for most panels |
| `.btn-primary` / `.btn-secondary` / `.btn-danger` | Button styles |
| `.input` | Form fields |
| `.gradient-text` | Headline accent |
| `.animate-fade-in` / `.animate-slide-in` | Entry animations |

Shared React components are in `src/components/ui` (`Button`, `Input`, `Select`,
`Modal`, `DataTable`, `Badge`, `PageHeader`, `LoadingSpinner`). Prefer these over
raw Tailwind on new screens so the look stays consistent.

`cn()` in `src/lib/utils.ts` merges class names via `clsx` + `tailwind-merge`, so
later classes correctly override earlier ones.

### Project layout

```
src/
  app/
    (auth)/        login, forgot-password, reset-password
    (dashboard)/   the application, wrapped by the sidebar layout
    api/           route handlers
    auth/callback/ Supabase email-link exchange
  components/      ui/, layout/, ai/, contracts/
  lib/
    ai/            providers, tools, schema-context, crypto
    supabase/      client, server, middleware helpers
    session.ts     resolves the app session (tenant, role, permissions)
    api.ts         withTenant() wrapper used by every API route
prisma/schema.prisma
```

## When something doesn't work

| Symptom | Cause |
|---|---|
| `Cannot read properties of undefined (reading 'findFirst')` | The dev server booted before a Prisma model existed. Node caches the client at startup - **restart the dev server**. |
| Changes to `.env` seem ignored | Next reads `.env` only at startup. Restart. |
| Password reset email never arrives | Supabase's built-in sender is rate-limited and development-only. Configure SMTP under **Authentication → Emails**. |
| Reset link opens but says the link expired | `http://localhost:3000/auth/callback` is missing from Supabase → Redirect URLs. |
| `Can't reach database server` | Wrong connection string, or the Supabase project is paused (free tier pauses after inactivity). |
| Signed in, but every page bounces to `/login` | The Supabase user has no matching app user or tenant - see step 5. |

## How it fits together

```
Browser ──▶ Next.js (Vercel or local)
                │
                ├── Supabase Auth ......... who you are (login, reset, MFA)
                ├── Supabase Postgres ..... your data, via Prisma
                └── Anthropic / OpenAI .... the AI assistant (optional)
```

Authentication is Supabase's; **authorisation is the app's** - which tenant you
belong to, your role, and your permissions all live in the app database and are
resolved on every request.
